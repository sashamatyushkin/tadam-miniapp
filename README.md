# Та-дам · Telegram Mini App

«Та-дам — и подарок готов». Подбор идей подарков по поводу, получателю, бюджету и интересам:
подборка → вишлист → намёк → новый пользователь.

**Живая версия (GitHub Pages):** https://sashamatyushkin.github.io/tadam-miniapp/
**Бот:** [@tadamapp_bot](https://t.me/tadamapp_bot) — кнопка «Открыть Та-дам» в чате с ботом

Это **работающий прототип фронтенда** по мокапам, брендбуку и документу «Структура приложения».
Он открывается в Telegram, проходится целиком руками и годится для теста продукта на людях.
Backend (PostgreSQL, платежи Stars, напоминания, админка) — следующий этап, см. «Что не сделано».

## 2. Что не сделано (нужен backend)

1. **Проверка `initData` на сервере.** Сейчас доступ и лимиты считаются на клиенте — это прототип,
   продавать доступ в таком виде нельзя.
2. **Оплата Telegram Stars:** invoice → `pre_checkout_query` → `successful_payment` → выдача
   entitlement. Сейчас кнопка «оплатить» открывает доступ в демо-режиме.
3. **Колесо на сервере.** Розыгрыш обязан считаться на backend (веса, лимиты, остатки,
   идемпотентность, журнал). Сейчас веса лежат в `js/config.js`, розыгрыш — `crypto.getRandomValues`
   на клиенте: результат считается **до** анимации, но подделать его теоретически можно.
4. **Напоминания о датах.** Даты сохраняются, но сообщения шлёт бот с очередью (BullMQ/Redis).
5. **Рефералы:** подтверждение «новый пользователь + первый шаг онбординга», защита от накрутки.
6. **Админка:** категории, идеи, импорт CSV, веса колеса, цены, UGC-модерация, AuditLog.
7. **Наполнение premium-категорий:** сейчас по 12 идей, по документу нужно 40–50.
   Бесплатные заполнены полностью — по 20 идей (60 всего).
8. **Аналитика наружу** (ClickHouse/Amplitude/собственный API) и дашборды.

## 3. Как открыть в Telegram

Всё уже настроено: открой [@tadamapp_bot](https://t.me/tadamapp_bot), нажми **Start** —
и жми кнопку **«Открыть Та-дам»** в меню чата.

Настроено через Bot API: кнопка меню с Mini App, команды `/start` и `/help` в меню
(`/terms`, `/support`, `/paysupport` работают, но скрыты), описание бота. Бот отвечает на deep links вида `t.me/tadamapp_bot?start=h_<идея>` —
так работают намёки и приглашения.

**Одна необязательная настройка руками** (BotFather, ~1 минута): `/newapp` → выбрать бота →
название, описание, картинка 640×360 → Web App URL `https://sashamatyushkin.github.io/tadam-miniapp/` →
короткое имя, например `app`. После этого впиши его в `js/config.js` → `TELEGRAM.appName = 'app'`,
и ссылки-намёки станут открывать приложение мгновенно (`t.me/tadamapp_bot/app?startapp=…`),
без промежуточного сообщения от бота и без запущенного процесса бота.

Проверить можно и без Telegram — просто открыв ссылку в браузере.

## 3.1. Что сделать при переезде на боевой домен

1. Выложить приложение на свой домен с HTTPS.
2. BotFather → `/newapp` → @tadamapp_bot → название, описание, картинка 640×360,
   Web App URL нового домена, короткое имя (например `app`).
3. Вписать короткое имя в `js/config.js` → `TELEGRAM.appName`.
   После этого намёки и приглашения уходят ссылкой `t.me/tadamapp_bot/app?startapp=…`
   и открывают приложение мгновенно — без сообщения от бота и без запущенного процесса бота.
4. BotFather → *Bot Settings* → *Menu Button* → новый URL (или тем же вызовом `setChatMenuButton`).
5. Перевести бота с long polling на webhook с secret token.

## 4. Локальный запуск

```bash
python3 -m http.server 4173
# http://localhost:4173
```

Сборка не нужна: чистый ES-модульный фронтенд без зависимостей.

## 5. Структура

```
index.html          оболочка, подключение Telegram SDK
styles.css          дизайн-система из брендбука (Mango/Oat Milk/Coffee/Ice Cube, Bups + Nunito)
js/config.js        КОНФИГ: категории, фильтры, лимиты, цены, веса колеса, ссылки Telegram
js/data/ideas.js    база идей (180 шт.)
js/store.js         состояние, правила доступа, колесо, квест, CloudStorage
js/tg.js            мост к Telegram Mini Apps API
js/ui.js            примитивы: шторки, тосты, чипы, маскот
js/screens/*.js     экраны
assets/             шрифты, маскоты (12 поз), логотип
bot/bot.js          заготовка Telegram-бота (не запускалась — нужен токен и сервер)
```

Продуктовые правила намеренно вынесены в `js/config.js` — при переезде на backend этот файл
заменяется ответом API, компоненты не трогаются.

## 6. Шрифты и лицензии

* **Nunito** — SIL Open Font License 1.1, файл лицензии: `assets/fonts/Nunito-OFL.txt`.
* **Bups** — лицензия не приложена. Файл лежит в репозитории, чтобы приложение выглядело
  по брендбуку. **Перед публичным запуском нужно подтвердить, что лицензия допускает
  веб-использование и размещение в открытом репозитории.**
* Логотип и маскоты — PNG из исходников (маскоты нарезаны из общего листа, фон убран).
  Для production нужен финальный SVG: автотрассировку за утверждённый логотип выдавать нельзя.

## 7. Известные ограничения прототипа

* Всё считается на клиенте: премиум можно «выдать» себе через DevTools. Это нормально для теста
  продукта и недопустимо для продаж.
* Намёк передаёт идею через `startapp=h_<id идеи>`; ссылка на вишлист (`w_<токен>`) открывается
  как брендовая заглушка — содержимое чужого вишлиста без сервера не показать.
* Счётчик приглашённых друзей демонстрационный.
* Напоминания не приходят — нет бота на сервере.
