# Backend «Та-дам»

Один процесс: HTTP API + Telegram-бот + планировщик напоминаний. Ноль npm-зависимостей —
только встроенные модули Node (`node:http`, `node:sqlite`, `node:crypto`), поэтому запускается
без `npm install` и без сети.

Требуется **Node ≥ 22** (`node:sqlite`). Проверено на Node 25.9.

## Запуск

```bash
cd server
cp .env.example .env      # и вписать BOT_TOKEN
npm start                 # = node --env-file=.env index.js
```

Поднимется:
- API на `http://localhost:8787`
- бот (long polling): `/start`, `/help`, deep links `h_`/`w_`/`r`
- планировщик напоминаний: проверка каждые 15 минут

## Как подключить фронтенд

Фронтенд по умолчанию работает **без backend** — ровно как раньше. Чтобы он ходил в API,
адрес передаётся прямо в ссылке (сохраняется в localStorage браузера):

```
https://sashamatyushkin.github.io/tadam-miniapp/?api=https://<адрес-сервера>
```

Для теста с телефона localhost не подойдёт — нужен публичный HTTPS. Быстрее всего
временный туннель (аккаунт не нужен):

```bash
cloudflared tunnel --url http://localhost:8787
```

Он напечатает адрес вида `https://xxx.trycloudflare.com` — его и подставить в `?api=`.
Адрес живёт, пока запущен туннель, и меняется при каждом перезапуске.

## Что уже делает сервер

| Возможность | Эндпоинт | Зачем |
|---|---|---|
| Проверка личности | `POST /api/auth` | HMAC-проверка Telegram `initData` по официальному алгоритму. Поддельный initData отклоняется 401 |
| Доступ | `GET /api/access`, `POST /api/access/grant-test` | Premium перестал быть записью в localStorage телефона |
| Колесо | `POST /api/wheel/spin`, `GET /api/wheel/available` | Результат считает сервер (`crypto.randomBytes`), дневной лимит и идемпотентность по ключу — тоже |
| Важные даты | `GET/POST /api/dates`, `DELETE /api/dates/:id` | Даты живут в БД сервера, поэтому бот может напомнить, даже когда приложение закрыто |
| Вишлист по ссылке | `POST /api/wishlist/sync`, `POST /api/wishlist/revoke`, `GET /api/wishlist/:token` | Получатель открывает **настоящий** список. `GET` публичный (у получателя может не быть своей сессии), владелец не раскрывается, чужой токен перезаписать нельзя |

Напоминания: за 14, 7, 3 и 1 день до даты, с учётом переноса 29 февраля.
Ключ `(дата, офсет, год)` не даёт прислать одно и то же дважды даже после перезапуска процесса.

## Тесты

```bash
npm test        # статистика колеса, идемпотентность, дневной лимит
```

Проверяет: сумму весов, что повторный запрос с тем же ключом возвращает тот же результат,
что второй спин в сутки отклоняется, и что на выборке 20 000 фактическое распределение
не уходит от заданных весов больше чем на 12%.

## Чего ещё нет

- **Telegram Stars.** Оплата по-прежнему симулируется: `/api/access/grant-test` выдаёт доступ
  без денег. Реальный путь — invoice → `pre_checkout_query` → `successful_payment` — не подключён.
- **Webhook.** Бот работает long polling: годится локально, для production нужен webhook с secret token.
- **Реферальные спины.** Таблица `referrals` создана, начисление бонусных спинов не реализовано.
- **Админка.** CRUD идей, категорий, весов колеса и партнёрских ссылок (`photo`, `long`, `buy`
  в `js/data/ideas.js`) пока живёт в коде фронтенда, а не в БД.
- **Хостинг.** Сервер запускается локально. Постоянный публичный адрес требует хостинга —
  выбор и стоимость нужно согласовать отдельно.

## Архитектурное решение (ADR)

ТЗ рекомендует Fastify + Prisma/PostgreSQL. Здесь взяты встроенные `node:http` и `node:sqlite`,
чтобы backend запускался одной командой без `npm install`, сети и нативной сборки — это важно
для локального теста на машине владельца. SQL простой и переносимый: при переезде на Postgres
меняются `db.js` и способ подключения, бизнес-логика (`wheel.js`, `reminders.js`, `http.js`)
остаётся как есть.
